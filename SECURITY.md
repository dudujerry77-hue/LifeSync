# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| main    | :white_check_mark: |
| < 1.0   | :x:                |

(Once stable releases exist, this table will be updated.)

## Reporting a Vulnerability

We take security and privacy seriously. If you discover a vulnerability:

1. **Do not** open a public issue.
2. Email the maintainers at security@lifesync.dev (placeholder — replace with a real private contact or GitHub Security Advisories once enabled).
3. Include as much detail as possible: description, steps to reproduce, potential impact, and any suggested fixes.

We will acknowledge receipt within a reasonable timeframe and work with you on a coordinated disclosure.

## Preferred Practices

- Prefer private disclosure via GitHub Security Advisories when available.
- Give us reasonable time to fix issues before public disclosure.
- Avoid testing vulnerabilities against production systems that contain real user data.

## Development Security & Integrity

In addition to vulnerability reporting, the project enforces a strict **Security, Integrity, and No-Fake-Implementation Policy** for all development work.

See **[SECURITY_INTEGRITY.md](SECURITY_INTEGRITY.md)** for the full mandatory rules, including:

- No fake or simulated implementations presented as real
- Honest feature states (Planned → Implemented → Tested → Verified)
- Security-first design before implementation
- Verification only with concrete evidence
- Explicit handling of uncertainty and ambiguity that affects security or privacy

Thank you for helping keep LifeSync and its users safe.
